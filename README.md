1.Levels of Testing

        *Unit Testing
 Unit Testing is the first level. Developers test individual functions, methods, or classes in isolation, often with mocks or stubs replacing their dependencies. For example, a unit test might verify that a function calculating a discount returns the correct value for several inputs.
 
        *Integration Testing
Integration Testing checks whether separately developed modules work together correctly. Even when each unit works alone, problems often appear at the boundaries, such as mismatched data formats, incorrect API calls,

          *System Testing
The tester treats the software as a black box and checks functional behavior, along with non-functional aspects such as performance, security, usability, and reliability

            *Acceptance Testing
the system is ready for delivery and meets the business or user needs. It is often carried out by the client or end users, through formats such as User Acceptance Testing (UAT), alpha testing (in-house, before release), and beta testing (with a limited group of real users in their own environment).



2. Requirement Analysis

*Requirement analysis is the phase of the software development lifecycle in which the needs of stakeholders are identified, documented, refined, and validated before design and coding begin. Its purpose is to make sure the team builds the right system, not just a system that works.



*Common techniques include interviews, questionnaires, workshops, observation of existing workflows, reviewing existing documents and systems, and prototyping.


*analysis and modeling, where the gathered information is organized and checked for conflicts, gaps, and ambiguities. Analysts often create models such as use cases, data flow diagrams, entity-relationship diagrams, or user stories to represent how the system should behave. Requirements are also classified, usually into functional requirements (what the system must do) and non-functional requirements (qualities such as performance, security, scalability, and usability).


*Software Requirements Specification (SRS) document. A good requirement is clear, complete, consistent, testable, and traceable to a business need.


*requirement management continues throughout the project. This includes tracking changes, maintaining traceability between requirements and tests, and managing stakeholder expectations.
